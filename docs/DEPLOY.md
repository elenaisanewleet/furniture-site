# Публикация сайта

Сайт статический: Astro собирает папку `dist/` из готового HTML. Никакого
Node на хостинге для показа сайта не нужно — только раздача файлов.

Отдельно от сайта живёт **приём заявок** (`server/index.mjs`). Это
единственная часть, которой нужен настоящий сервер. Ниже про неё есть
отдельный раздел — без неё сайт работает, но форма честно пишет, что заявки
пока не принимаются.

---

## Vercel

### 1. Подключить репозиторий

Vercel → **Add New → Project** → выбрать `elenaisanewleet/furniture-site`.

Настройки Vercel подхватит сам из `vercel.json` в корне: команда сборки,
папка `dist`, слэш на конце адресов, заголовки кэша для шрифтов. Менять
предложенные поля не нужно.

**Production Branch.** В репозитории одна ветка,
`claude/furniture-workshop-site-ulyanovsk-d8ujer`, и она же основная —
Vercel возьмёт её сам. Если веток станет больше, ветку для продакшена
задают в Settings → Git.

### 2. Задать переменные окружения

Settings → **Environment Variables**. Обязательная одна:

| Имя | Значение | Зачем |
|---|---|---|
| `SITE_URL` | `https://ваш-домен.ru` | Канонические адреса, `sitemap-index.xml`, `robots.txt` |

Без неё сайт соберётся, но во всех canonical и в карте сайта будет стоять
заглушка `masterskaya.example.ru`. Для поиска это хуже, чем отсутствие
сайта: Яндекс и Google увидят ссылки на несуществующий домен.

`SITE_URL` читается **во время сборки**. После её изменения нужен
пересбор — Deployments → ⋯ → Redeploy.

Остальные — по мере готовности:

| Имя | Значение | Что включает |
|---|---|---|
| `PUBLIC_LEAD_ENDPOINT` | адрес обработчика заявок | Форма начинает реально отправлять |
| `PUBLIC_TG_BOT` | имя бота без `@` | Кнопки «Продолжить в Telegram» |
| `PUBLIC_METRIKA_ID` | номер счётчика | Яндекс.Метрика |

Пустая переменная = функция просто не появляется на сайте. Это нормальное
рабочее состояние, а не поломка.

### 3. Домен

Settings → **Domains** → добавить домен и прописать у регистратора записи,
которые покажет Vercel. После этого не забыть поправить `SITE_URL` на
боевой домен и пересобрать.

### Что нужно знать про сборку

`npm run build` — это `astro check && astro build`. Проверка типов идёт
до сборки, и ошибка типов **уронит деплой**. Так и задумано: лучше не
выложить, чем выложить сломанное. Если когда-нибудь понадобится выкатить
в обход проверки, в `vercel.json` меняется `buildCommand` на
`npm run build:fast`.

## Обычный хостинг (ISPmanager, cPanel, любой с FTP/SSH)

Сайт статический, поэтому подходит **любой** тариф — Node, PHP и базы не
нужны. Вся сборка занимает 60 файлов и 3,2 МБ.

Разница с Vercel одна: собирает не хостинг, а вы у себя. `SITE_URL`
подставляется **в момент сборки**, значит домен нужно указать в команде.

### Разово

1. Настроить SSH-ключ в панели хостинга (или взять доступы по FTP).
2. Узнать путь до корня сайта: обычно `public_html`, `www` или
   `domains/ваш-домен.ru/public_html`.

### Каждый раз

```bash
SITE_URL=https://ваш-домен.ru \
DEPLOY_HOST=u123456@ssh.hosting.ru \
DEPLOY_PATH=/home/u123456/public_html \
./scripts/deploy.sh
```

Скрипт собирает сайт с нужным доменом, прогоняет проверку доступности и
заливает `dist/` через rsync. Посмотреть, что уедет, ничего не меняя:
добавьте `--dry-run`.

Если SSH нет и есть только FTP — то же самое руками: собрать
`SITE_URL=https://ваш-домен.ru npm run build` и залить **содержимое**
папки `dist/` (не саму папку) в корень сайта любым FTP-клиентом.

### Настройка веб-сервера

В `public/.htaccess` уже лежит конфигурация для Apache и LiteSpeed — а это
почти весь российский шёред-хостинг. При сборке она попадает в `dist/` и
уезжает вместе с сайтом, делать ничего не нужно. Там: кодировка,
страница 404, редирект на https, кэш, сжатие, заголовки безопасности.

**Про кодировку отдельно.** Часть хостингов по умолчанию отдаёт latin-1, и
тогда весь русский текст превращается в крокозябры — сайт выглядит
сломанным целиком, хотя с ним всё в порядке. `AddDefaultCharset utf-8` в
`.htaccess` это закрывает. Если после первой выкладки видите «ÐœÐ°ÑÑ‚ÐµÑ€»
— значит хостинг `.htaccess` не прочитал, ищите настройку кодировки в
панели.

Если хостинг на **nginx** (Timeweb, Selectel и подобные), `.htaccess` не
читается, и нужный кусок конфига выглядит так:

```nginx
charset utf-8;
charset_types text/html text/css application/javascript application/json image/svg+xml;

index index.html;
error_page 404 /404.html;

# trailingSlash: 'always' — каждая страница лежит папкой с index.html
location / {
    try_files $uri $uri/ =404;
}

location /_astro/ {
    add_header Cache-Control "public, max-age=31536000, immutable";
}

location /fonts/ {
    add_header Cache-Control "public, max-age=31536000";
}

location ~* \.html$ {
    add_header Cache-Control "public, max-age=0, must-revalidate";
}

add_header X-Content-Type-Options "nosniff" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
add_header X-Frame-Options "SAMEORIGIN" always;

gzip on;
gzip_types text/css application/javascript application/json image/svg+xml;
```

### Про `/admin/`

Это редактор контента Decap CMS. Он git-овый: правки уходят коммитами в
GitHub, а для входа нужен OAuth-посредник, которого на обычном хостинге
нет. То есть страница откроется, но войти в неё не выйдет.

Поэтому `scripts/deploy.sh` папку `admin/` не выкладывает. Пока редактор
не настроен, ей на боевом сайте делать нечего. Локально он работает без
всякой настройки:

```bash
npx decap-server   # в одном окне
npm run dev        # в другом, дальше открыть /admin/
```

## Приём заявок

Форма отправляет данные на адрес из `PUBLIC_LEAD_ENDPOINT`. Пока он пуст,
форма показывает сообщение, что приём не подключён, и предлагает позвонить.

Обработчик `server/index.mjs` — обычный Node-процесс без зависимостей: он
принимает multipart, проверяет поля, кладёт файлы на диск и пишет строку в
JSONL. На статическом хостинге Vercel он работать не будет, для него нужен
хостинг с Node — тот второй, который уже есть.

Порядок:

1. Поднять `server/index.mjs` на Node-хостинге, задать ему переменные из
   `.env.example` (раздел «сервер приёма заявок»).
2. В `ALLOW_ORIGIN` вписать домен сайта — иначе браузер не пропустит
   запрос с одного домена на другой.
3. В `REDIRECT_URL` — адрес страницы `/spasibo/` на боевом домене.
4. На Vercel задать `PUBLIC_LEAD_ENDPOINT` = адрес этого обработчика и
   пересобрать.

**Данные людей.** Заявки содержат имя, телефон и фотографии квартиры —
это персональные данные. По 152-ФЗ данные российских граждан должны
храниться на серверах в России, поэтому обработчик и загруженные файлы
должны стоять на российском хостинге. Сам сайт (статика без персональных
данных) под это требование не подпадает и может лежать где угодно.

**До запуска формы** нужно заполнить `/privacy/` и `/soglasie/` — сейчас
там шаблоны-рыба. Собирать заявки без опубликованной политики нельзя.

## Проверить перед публикацией

```bash
npm run build     # проверка типов + сборка
npm run a11y      # доступность: 54 загрузки страниц, должно быть 0 нарушений
```

И глазами — на собранном, а не на dev-сервере:

```bash
npm run preview                    # http://localhost:4321
npm run shot / 1280 home.png --full   # скриншот всей страницы
```
