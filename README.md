# Сайт мебельной мастерской · Ульяновск

Сайт построен вокруг одного действия:

> **Покажите, что нужно сделать. С остальным разберёмся.**

Посетитель не обязан знать, как называется деталь, какой у него тип петли и
сколько сантиметров в нише. Он фотографирует задачу — дальше работает
мастерская. Один и тот же паттерн «показать задачу» повторяется на каждой
странице: после статьи, на странице ремонта, на карточке работы.

Вторая функция сайта — SEO-машина: каждая выполненная работа становится
отдельной индексируемой страницей и наращивает органический трафик.

Три вещи, которых нет у местных конкурентов:

1. **Определитель детали** (`/opredelitel/`) — каталог фурнитуры наоборот.
   Вход не по названию механизма, а по тому, где деталь стоит и как её
   называют вслух: «рельса», «дверца висит», «минификс». Схемы нарисованы,
   а не сфотографированы — для опознания линия понятнее фотографии.
2. **Передача заявки в Telegram.** После отправки человек получает номер
   обращения и кнопку «Продолжить в Telegram» — дальше переписка идёт там,
   а не «вам перезвонит незнакомый номер».
3. **Настоящие фотографии мастерской** вместо стоковых интерьеров.

## Быстрый старт

```bash
npm install
npm run dev          # http://localhost:4321
```

Сборка:

```bash
npm run build        # проверка типов + статическая сборка в dist/
npm run preview
```

| Команда | Что делает |
|---|---|
| `npm run dev` | Дев-сервер |
| `npm run build` | `astro check` + сборка |
| `npm run build:fast` | Сборка без проверки типов |
| `npm run review` | **Режим проверки**: показывает неподтверждённые пункты |
| `npm run photos` | Пересобирает `docs/PHOTO-BRIEF.md` (после `build`) |
| `npm run server` | Локальный приём заявок (см. ниже) |
| `npm run bot` | Telegram-мост клиент ↔ оператор |
| `npm run a11y` | axe-core по 18 страницам в трёх режимах |

## Главное правило: сайт ничего не выдумывает

Это самая важная особенность проекта. Всё, что не подтверждено мастером, на
публичном сайте **не появляется** — не потому что копирайтер об этом помнил,
а потому что так устроен код.

Каждый факт несёт статус:

| Статус | Что значит | Публикуется |
|---|---|---|
| `fact` | подтверждено | да |
| `hypothesis` | вероятное направление | нет |
| `needs-confirmation` | нужен ответ мастера | нет |

Механика — `src/lib/facts.ts`. Всё, что не `fact`, отфильтровывается на
этапе сборки.

**Посмотреть, что скрыто:**

```bash
npm run review && npm run preview
```

Появится оранжевая полоса и страница **`/review/`** — единый список:
вопросы к мастеру, неподтверждённые утверждения, демонстрационные работы и
все фотослоты. С ней можно сесть и пройти по пунктам.

Сейчас не подтверждено и потому не публикуется: география выезда, адрес,
сроки, гарантии, цены, бренды фурнитуры, имя мастера, название мастерской,
мессенджеры, работа с мебелью из сетевых магазинов.

Телефон и название бизнеса меняются в одном месте — `src/data/site.ts`.

## Приём заявок

Из коробки форма работает в демонстрационном режиме: она честно сообщает,
что обработчик не подключён, вместо того чтобы имитировать отправку.

Чтобы включить приём:

```bash
# 1. поднять сервер заявок
node server/index.mjs                    # слушает :8787, пишет в ./data

# 2. собрать сайт с адресом обработчика
PUBLIC_LEAD_ENDPOINT=https://api.example.ru/submit npm run build
```

`server/index.mjs` — референсная реализация без зависимостей: валидация,
защита от ботов, лимит запросов, запись файлов на диск и JSONL-журнал
заявок. Архитектура соответствует принципу «персональные данные остаются у
вас»:

```
браузер --HTTPS--> сервер заявок --> файлы + JSONL на вашем диске
                                 \-> мессенджер: только уведомление
```

В мессенджер уходит факт заявки и её тип — **без телефона, текста и
фотографий**. Включается переменными `TELEGRAM_BOT_TOKEN` и
`TELEGRAM_CHAT_ID`.

Форма работает и **без JavaScript**: тогда это обычная форма, которая
постится напрямую и получает редирект на `/spasibo/`.

> Перед публичным сбором заявок заполните `/privacy/` и `/soglasie/` —
> сейчас там заготовки с пометками `[НУЖНО УТОЧНИТЬ]`.

## Telegram

Заявка с сайта и переписка в мессенджере — это одна и та же нить.

```bash
PUBLIC_TG_BOT=имя_бота npm run build        # кнопка появляется на сайте
TELEGRAM_BOT_TOKEN=… TELEGRAM_CHAT_ID=… npm run bot
```

Как это работает:

```
человек отправил фото ──► сервер выдал номер ULY-…
        │
        └─ кнопка «Продолжить в Telegram» → t.me/бот?start=ULY-…
                    │
                    ▼
            бот связывает чат с заявкой
                    │
   оператор видит заявку ◄──┴──► отвечает reply — ответ уходит клиенту
```

Клиент может дослать фотографии и голосовые прямо в переписку. Оператор
отвечает обычным reply на сообщение заявки — бот сам знает, кому его
переслать. Персональные данные при этом остаются в базе сайта: бот хранит
только связку «чат ↔ номер заявки».

## Фотографии

**Мастерская снята по-настоящему** — 36 фотографий обработаны и разложены
по слотам (`npm run photos` показывает карту). Из них собраны первый экран,
раздел «где всё это происходит», оборудование и блок про сортированный
крепёж.

При импорте с фотографий снимаются EXIF и GPS-координаты, они ужимаются в
webp и к каждой генерируется 24-пиксельная размытая заглушка для плавной
подгрузки. Повторить импорт: `node scripts/ingest-photos.mjs <папка>`.

Чего пока нет — снимков готовой мебели и портрета мастера. Там остались
оформленные заглушки, которые не выглядят как сломанная вёрстка и подписаны
именем нужного файла.

**Чтобы поставить настоящую фотографию, нужно положить файл — и всё:**

```
public/photo/hero-workshop.webp
```

Вёрстку менять не нужно, компонент сам подхватит файл. Пропорции и брифы на все
слоты — в **`docs/PHOTO-BRIEF.md`** (генерируется `npm run photos`). Там же
общий стиль съёмки и список того, чего в кадре быть не должно.

Лицо мастера нигде не выдумано: используются руки, инструмент и процесс,
а под настоящий портрет оставлено оформленное место.

## Контент без разработчика

Всё содержимое — markdown-файлы:

```
src/content/services/   услуги и SEO-страницы
src/content/projects/   работы
src/content/journal/    статьи
src/content/faq/        вопросы
src/content/areas/      районы обслуживания
```

Схема с проверкой при сборке — `src/content.config.ts`. Правила написания —
`docs/CONTENT-SPEC.md` (тон, запрещённые утверждения, обязательная структура).

Есть и визуальный редактор — Decap CMS, `/admin/`. Локально:

```bash
npx decap-server   # в одном терминале
npm run dev        # в другом → /admin/
```

Для работы на боевом сайте нужно указать репозиторий и подключить GitHub
OAuth в `public/admin/config.yml`.

### Добавить выполненную работу

Это главный источник роста трафика.

1. `src/content/projects/новая-работа.md`
2. Заполнить: задача → как было → что усложняло → что сделали → результат.
3. Положить фотографии в `public/photo/`.
4. **Поставить `placeholder: false`** — иначе работа останется помеченной как
   шаблон и закрытой от индексации.

Демонстрационные работы (`placeholder: true`) видно на сайте, но они честно
подписаны «шаблон · не реальная работа», закрыты `noindex` и не попадают в
sitemap.

## Архитектура

```
src/
  content.config.ts   контентная модель (Zod)
  data/site.ts        NAP, контакты, статусы подтверждения
  data/nav.ts         навигация: каталог + вход по проблеме
  lib/facts.ts        фильтр неподтверждённых утверждений
  lib/photo.ts        подстановка настоящих фото вместо заглушек
  lib/schema.ts       schema.org (только подтверждённые поля)
  data/parts.ts       детали для определителя + схемы
  components/         Photo, TaskForm, PartFinder, ShowTask, BeforeAfter …
  pages/              маршруты
  scripts/            клиентский JS (~11 КБ gzip)
server/index.mjs      референсный приём заявок
server/bot.mjs        Telegram-мост клиент ↔ оператор
scripts/ingest-photos.mjs   импорт фотографий (EXIF, webp, LQIP)
scripts/photo-brief.mjs     карта фотослотов
scripts/a11y.mjs            гейт доступности
docs/PRODUCT-MODEL.md внутренняя продуктовая модель
docs/CONTENT-SPEC.md  правила написания контента
docs/PHOTO-BRIEF.md   брифы на фотографии (генерируется)
```

Стек: **Astro** (статическая генерация), никаких UI-фреймворков. Весь
интерактив — ванильный TypeScript, подключается один раз на страницу.
Переходы между страницами — View Transitions; вся клиентская обвязка
идемпотентна, потому что при таких переходах она запускается заново.

### Навигация под две модели поведения

- **Знаю, что нужно**: шкафы, кухни, гардеробные — меню «Услуги».
- **Знаю только проблему**: сломалось, не помещается, не знаю что это —
  блок на главной и страница `/chto-sluchilos/`.

Обе ведут в одну форму, с предзаполненным первым шагом.

## SEO

- отдельный URL у каждой коммерческой страницы и каждой работы;
- уникальные `title` / `description`, один `H1`, self-canonical;
- хлебные крошки + `BreadcrumbList`;
- `LocalBusiness`, `Service`, `FAQPage`, `Article`;
- `sitemap-index.xml` с приоритетами по коммерческой значимости;
- `robots.txt` генерируется под домен сборки;
- служебные страницы закрыты `noindex`, а не только в robots.txt;
- `meta keywords` не используется.

Домен задаётся при сборке:

```bash
SITE_URL=https://example.ru npm run build
```

### Аналитика

События уходят в `dataLayer` и в Яндекс.Метрику (`PUBLIC_METRIKA_ID`).
Персональные данные не передаются — только тип обращения, шаг формы и
страница. Полный список событий — `src/scripts/analytics.ts`.

## Доступность и производительность

- семантическая разметка, `<dialog>`, `<details>`, настоящие `fieldset`;
- видимый фокус, ссылка «к содержанию», управление с клавиатуры;
- `prefers-reduced-motion` и `prefers-color-scheme` учитываются;
- у изображений заданы пропорции — сдвигов макета нет;
- шрифты локальные, только кириллица и латиница (120 КБ на 4 файла);
- сравнение «до/после» работает клавиатурой (это `input[type=range]`).

## Что осталось сделать

1. Пройти `/review/` вместе с мастером и снять пометки.
2. Заменить заглушки настоящими фотографиями (`docs/PHOTO-BRIEF.md`).
3. Заполнить `/privacy/` и `/soglasie/` — до этого не собирать заявки.
4. Поднять приём заявок и подключить уведомления.
5. Опубликовать первые настоящие работы вместо шаблонов.
6. Подключить Яндекс Вебмастер, Метрику и карточку организации.
7. Поднять Telegram-бота и задать `PUBLIC_TG_BOT`.
8. Дополнить определитель деталями, с которыми реально приходят.
