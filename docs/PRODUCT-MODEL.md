# Внутренняя продуктовая модель

Служебный документ. Не публикуется, не отражается в интерфейсе.
Всё, что построено на сайте, выводится отсюда.

---

## 0. Что взято из исследования

Из приложенного исследования ~100 сайтов отобрано следующее. Ничего не
скопировано целиком; взяты механики, а не оформление.

### Механики, которые берём

| Источник паттерна | Что берём | Как переработано |
|---|---|---|
| A.Мебель, ArturMebel (расчёт по фото) | фото как точка входа | Локальные конкуренты это уже умеют, поэтому фото у нас — не «расчёт», а **постановка задачи**: фото + голос + референс + «не знаю, что это» |
| BigMebel (8-шаговый quiz) | пошаговость | Сжато до 4 шагов и первый шаг отвечает на вопрос клиента, а не наш |
| Blum / Hettich / Häfele (каталоги фурнитуры) | таксономия деталей | Развёрнута на 180°: не «тип механизма», а «что у вас происходит» |
| California Closets, Inspired Closets | продажа процесса, а не предмета | Блок «как мы работаем» из 5 шагов без корпоративщины |
| CenterMebel73, Toolskiy (проекты) | проект как документ | Шаблон проекта = задача → ограничения → решение → результат |
| Pickawood | «пришлите свой рисунок» | Расширено до «референс из Pinterest / скриншот / эскиз» |
| Tylko, IKEA planners | мгновенная обратная связь | **Отброшено.** Конфигуратор требует стандартизованного продукта; сила мастерской в обратном |
| Sharps / Hammonds / Neville Johnson | before/after как доказательство | Компонент готов, наполняется только реальными фото |
| Jali, DIY Alcove Cabinets | ниша как отдельный сценарий | Отдельный интент «шкаф в нишу» внутри шкафов |

### Что осознанно НЕ делаем в MVP

3D-конфигуратор · AR · личный кабинет · автоматический калькулятор цены ·
AI-распознавание фурнитуры · сотни сгенерированных SEO-страниц · большая CRM ·
региональные поддомены · агрессивные промо-механики (скидки, таймеры).

## 1. Пользовательские намерения

### Первичные (приводят деньги)

| ID | Намерение | Формулировка клиента | Точка входа |
|---|---|---|---|
| P1 | Сломалось, надо починить | «дверца перекосилась», «ящик выпадает» | `/remont-mebeli/` |
| P2 | Нужна деталь, названия не знаю | «вот эта штука отвалилась» | `/furnitura/`, `/detali-na-zakaz/` |
| P3 | Нужна мебель в конкретное место | «шкаф в нишу», «кухня в хрущёвку» | `/shkafy-na-zakaz/`, `/kuhni-na-zakaz/` |
| P4 | Хочу как на картинке | «видел на Pinterest» | `/mebel-po-foto/` |
| P5 | Переделать, а не покупать новое | «можно фасады поменять?» | `/peredelka-mebeli/` |
| P6 | Нестандартный размер | «не влезает», «таких не бывает» | `/nestandartnaya-mebel/` |

### Вторичные

S1 сравнение «починить или купить новое» · S2 проверка компетентности перед
звонком · S3 узнать название детали · S4 понять, как считается цена ·
S5 понять, поедет ли мастер ко мне.

**Ключевой инсайт:** P1, P2, P5 — низкий чек, но именно они дешевле всего
покупаются в поиске и создают доверие, из которого через год вырастает P3.

## 2. Две ментальные модели навигации

Сайт обслуживает обе одновременно, одним набором страниц.

```
MODEL A — знаю предмет          MODEL B — знаю только проблему
Шкафы  Кухни  Гардеробные       Сломалось  Не закрывается
Столы  Полки  Прихожие          Не помещается  Хочу такое же
        │                        Нужна деталь  Не знаю, что это
        │                               │
        └────────────┬──────────────────┘
                     ↓
            одна и та же форма
             «Показать задачу»
```

Реализация: в шапке — Model A (каталог услуг). На главной сразу под первым
экраном — Model B (`ProblemGrid`). Оба ведут в один flow с разными пресетами.

## 3. Конверсионная воронка

```
Вход (organic / прямой)
   ↓
Узнавание: «здесь можно просто показать» — 1 экран, < 5 секунд
   ↓
Выбор способа: фото · слова · голос · звонок
   ↓
Шаг 1  Что нужно сделать          6 карточек + «пока не знаю»
   ↓
Шаг 2  Покажите                   фото / референс, drag&drop, камера
   ↓
Шаг 3  Своими словами             необязательно, + голос
   ↓
Шаг 4  Как связаться              телефон, обязателен только он + согласие
   ↓
Отправлено                        без обещания срока ответа
   ↓
Елена: 1–3 уточняющих вопроса → структурированная задача → мастер
```

**Обязательный минимум для отправки: задача + телефон + согласие.**
Ни имя, ни размеры, ни бюджет, ни email не обязательны и не спрашиваются
на первом шаге.

Каждый шаг можно пропустить, кроме контакта. Прогресс сохраняется в
`sessionStorage` — возврат на сайт не теряет вложенные фото.

## 4. Конверсионные события

Отправляются в `dataLayer` и в Яндекс.Метрику (`reachGoal`), без
персональных данных: только тип, шаг и страница.

```
hero_cta_click          request_type_selected     voice_description_started
photo_upload_started    form_started              voice_description_completed
photo_upload_completed  form_step_completed       phone_click
reference_added         form_completed            messenger_click
form_abandoned          project_opened            service_opened
```

## 6. SEO-архитектура

Три слоя, связанные перекрёстными ссылками:

```
КОММЕРЧЕСКИЙ          ДОКАЗАТЕЛЬНЫЙ          ИНФОРМАЦИОННЫЙ
услуги                проекты                 статьи + FAQ
  │                      │                        │
  │ «что можно сделать»  │ «вот как сделали»     │ «как это устроено»
  └──────────────────────┴────────────────────────┘
                    все ведут в один CTA
```

Каждая коммерческая страница обязана содержать: H1 · интро от задачи
клиента · формулировки проблемы словами клиента · примеры работ ·
как происходит работа · фото · FAQ · связанные услуги · CTA · внутренние
ссылки на проекты и статьи.

**Growth loop:** заказ → фотографии → страница проекта → внутренние ссылки
на услугу → рост услуги в выдаче → новые заказы.

Ключевые сущности размечены: `LocalBusiness`, `Service`, `BreadcrumbList`,
`FAQPage`, `Article`, `ItemList`. `meta keywords` не используется.

## 7. Контентные модели

Все — файлы markdown с front-matter, схема в `src/content.config.ts`.

| Тип | Ключевые поля | Кто добавляет |
|---|---|---|
| `services` | intent, problems[], examples[], process[], faq[], related[], cta | владелец |
| `projects` | **placeholder**, facts{}, task, situation, constraints[], solution, result, beforeAfter | владелец |
| `journal` | query, answer, topic, services[], cta | владелец |
| `faq` | q, a, group, status | владелец |
| `areas` | name, kind, status | владелец |

Каждая запись несёт `status`: `fact` | `hypothesis` | `needs-confirmation`.
Публикуется только `fact` (см. `src/lib/facts.ts`).

## 9. Модель изображений

Одно правило: **вёрстка не знает, настоящая фотография или заглушка.**

```
src/data/images.ts   манифест: имя · alt · пропорции · бриф на съёмку
public/photo/{name}.webp   реальный файл — если есть, используется он
        ↓ если файла нет
<Photo> рисует оформленную заглушку с именем ассета
```

Замена фотографии = положить файл с тем же именем. Ни строчки вёрстки.
Брифы для генерации/съёмки — `docs/PHOTO-BRIEF.md`.

## 10. Тон

Пишем как человек, который каждый день чинит мебель, а не как отдел
маркетинга.

| Нельзя | Можно |
|---|---|
| «полный комплекс услуг по изготовлению» | «сделаем шкаф под ваш проём» |
| «оставьте заявку на бесплатную консультацию» | «покажите, что нужно сделать» |
| «индивидуальный подход» | «беремся за то, от чего отказываются» |
| «широкий ассортимент фурнитуры» | «не знаете, как называется деталь — сфотографируйте» |
| «ЗАКАЖИ СЕЙЧАС», «только сегодня» | — не используется вообще |

Запрещённые к публикации утверждения до подтверждения: срок изготовления,
гарантия, цена, стаж, количество проектов, бренды фурнитуры, оборудование,
адрес приёма клиентов, география выезда, отзывы, рейтинг, сертификаты.
